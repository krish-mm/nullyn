v1 laptop prototype

Try Nullyn AI on a laptop.

The v1 prototype runs the same algorithm in real time on a laptop. A USB audio interface does the conversion, not this software. Commands below are taken from the public repository README. The project is in active development, and collaborators are welcome.

What you need

A 64-bit laptop, Python 3.10+, and an interface with an XLR input.

These starting points are taken from the repository README. Windows ASIO performance, macOS CoreAudio performance, USB analog-to-analog round-trip, thermal throttling, and driver quality on any particular interface have not been measured, and are not claimed here.

  • Laptop

    A 64-bit laptop that can run Python 3.10 or newer. For closed-loop v1, start at 48 kHz with a 128–256 sample callback (about 2.7–5.3 ms of buffer latency), close other heavy applications, and watch the callback times that nullyn rt prints. If p95 exceeds the buffer, raise --blocksize.

  • Interface

    At least one XLR microphone input, and a line-level output back to the console. A second input is required for the closed-loop speaker-feed reference. Prefer one interface for both input and output.

  • Software

    The public package at github.com/krish-mm/nullyn-ai-defeedback, installed with the realtime extra for the USB path. Released under the MIT License.

A measured offline CPU table, taken on a Linux development VM, lives in the README’s minimum laptop requirements. Those figures are process time, not analog I/O latency, and not a venue result.

Steps

Clone, install, list devices, run.

Every flag in the run command comes from the README. "Scarlett" is the documented example device name — use the names your interface reports.

  1. Step 1

    Clone the repo

    On your laptop:

    git clone https://github.com/krish-mm/nullyn-ai-defeedback
cd nullyn-ai-defeedback

  2. Step 2

    Connect the interface

    Plug the microphone into an XLR input on the USB audio interface, and the interface’s line output into the console or speaker path. For the closed loop, feed a line-level copy of the speaker feed into a second input. Then connect the interface to the laptop over USB.

  3. Step 3

    Install the package

    Python 3.10 or newer. The realtime extra is the one required for the USB interface path.

    python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -e ".[dev]"
# optional, for the real-time USB interface path:
pip install -e ".[realtime]"

  4. Step 4

    List your devices, then pick input and output

    Input and output can be different devices (--input-device and --output-device). Using two unsynchronised interfaces for input and output is possible in the CLI but is a poor idea for a feedback loop; prefer one interface for both.

    nullyn rt --list-devices

  5. Step 5

    Run it in real time

    The command prints the callback block size in milliseconds, PortAudio’s reported input and output latency if the driver provides it, and running callback CPU time (median / p95 / max). Those figures are not an analog-to-analog measurement. --soundcheck 3 runs three seconds of closed-loop path identification (probe noise) before passing audio.

    nullyn rt \
  --input-device "Scarlett" \
  --output-device "Scarlett" \
  --mic-channel 1 \
  --ref-channel 2 \
  --output-channel 1 \
  --samplerate 48000 \
  --blocksize 128

From the README

If something does not behave.

Only notes already written in the repository README are listed here. We have not added extra troubleshooting.

  • Callback times If p95 exceeds the buffer, raise --blocksize. Real-time audio has to meet the budget almost every block, not on average.
  • One interface Prefer one interface for both input and output. Two unsynchronised interfaces are possible in the CLI but are a poor idea for a feedback loop.
  • Line-level reference The software expects a line-level speaker-feed reference, not a speaker-level tap unless it has been passed through a pad.
  • What the printed times are not Callback size, PortAudio’s reported latency, and callback CPU time are not an analog-to-analog measurement.
  • Not yet measured Windows ASIO, macOS CoreAudio, USB analog-to-analog round-trip, thermal throttling, and driver quality on a particular interface have to be measured on the laptop and interface you actually use.
  • Soundcheck --soundcheck 3 runs three seconds of closed-loop path identification (probe noise) before passing audio.
